# 架构说明（为什么这样分层）

## 一句话

**接口层薄、数据层厚、UI 层只认状态。** 学校哪天升级正方、字段改名、加验证码，
改动只落在 `lib/data/api/` 和 `lib/core/auth/` 两个目录里，页面一行不用动。

## 四层职责

```
features/   页面：只读 AppState、只调 AppState 的方法，不认识 HTTP，也不认识正方
   ↓
app/app_state.dart   全局状态：登录态、数据、加载/错误/离线标记、偏好
   ↓
data/api/zf_api.dart 接口层：发请求 → 拿原始 JSON → 宽松解析成模型
   ↓
core/       auth（握手/RSA）、net（Cookie HTTP）、wifi（srun）、theme
```

### 为什么接口要"返回原始报文"

`ApiResult<T>` 同时带 `data` 和 `raw`：

1. `raw` 落进 SharedPreferences → 断网/教务挂了还能看昨天的课表
2. 出问题时能直接对比"上次拿到什么、这次拿到什么"，不用靠猜
3. 学校改字段时，新加一个 key 到 `pick(m, [...])` 的候选列表就能兼容，不用重写解析

这是参照项目（ZZUPocket）踩坑经验里最值钱的一条，直接照抄。

### 为什么不用状态管理框架

现在只有一个全局 store，页面之间没有共享复杂状态。单例 + ChangeNotifier 足够，
代码量少、调试直观。真要换 Riverpod，页面只依赖 `AppState` 的那几个方法，
替换成本是 `app_state.dart` 一个文件。

### 为什么不用 dio / retrofit

正方只需要一个 JSESSIONID，`dart:io HttpClient` + 自己维护 Cookie Map 就够；
少一层依赖，少一个在国内网络下可能抽风的包。

## 毛玻璃的性能策略

关键判断：**不是所有东西都该模糊**。

| 层 | 做法 | 理由 |
|---|---|---|
| 背景 | 静态径向渐变"极光"，**零实时模糊** | 背景再模糊是白烧 GPU |
| 导航条 / 大标题 | `BackdropFilter` 真模糊 | 只有 2 个，面积小 |
| 课程块 / 列表行 | 半透明填充，**不模糊** | 一屏 20+ 个，逐个模糊中端机必掉帧 |

`GlassTheme.blurTier`（0 关 / 1 轻 / 2 标准 / 3 强）由用户在「更多 → 外观」里调，
调低时 `blurSigma` 直接变 0，`BackdropFilter` 整个不挂载。

## 坐标与单位

- 正方接口长度单位是"节次"（1-12）和"周次"（1-20），**不是**时间戳
- 作息时间表在 `core/constants.dart` 里是纯展示用的映射，跟排课无关
- 课表布局：`(day-1)*列宽` + `(startPeriod-1)*行高`，同一天重叠课程用贪心泳道并排

## 已知取舍

1. **课表只按"当前学期"取**（xnm/xqm 传空）。学期切换要等拿到真实报文里的
   `<select id="xnm">` 之后再做，避免猜错参数。
2. **离线缓存还没做按学期分键**的完整版，现在是"取最后一次成功的那份"。
3. **校园网自动认证**只有手动触发。后台自动需要前台服务 + `NetworkCallback`，
   还得处理安卓的省电策略（这机型是 i7 笔记本，但目标机是中端安卓，厂商省电更狠）。
